# Архитектура MailLens (MVP)

MailLens — сервис интеллектуальной категоризации почтового трафика на базе zero-shot
мультиязычных эмбеддингов с веб-интерфейсом и REST API.

---

## Компоненты системы

### 1. UI (Streamlit)
**Файл:** `ui/streamlit_app.py`

Функции:
- загрузка одного или нескольких писем (`.eml`, `.msg`)
- ввод пользовательских категорий (произвольные строки)
- настройка параметров:
  - `Top-N категорий`
  - `Threshold («Не определена»)`
- фильтрация результатов (только «Не определена»)
- просмотр таблицы результатов
- скачивание `results.csv`
- сброс результатов через API (`/results/reset`, если включён)

UI не содержит ML-логики — вся обработка выполняется на стороне API.

---

### 2. API (FastAPI)
**Файл:** `app/api.py`

Основные эндпоинты:
- `GET /health` — проверка доступности сервиса
- `POST /classify/batch` — batch-классификация писем
- `GET /export/results.csv` — выгрузка результатов
- `POST /results/reset` — очистка `results.csv` (опционально)

Ответственности API:
- приём файлов и параметров классификации
- парсинг писем и вложений
- построение канонического текста письма
- вызов ML-классификатора
- применение бизнес-правила «Не определена»
- логирование и сохранение результатов

---

### 3. Парсер писем
**Файл:** `app/email_parser.py`

Поддержка:
- `.eml` — стабильная (через стандартный `email`)
- `.msg` — best-effort (через `extract-msg`, если установлен)

Извлекаемые данные:
- тема письма (subject)
- тело письма (plain / html → text)
- ссылки (URLs)
- вложения:
  - `pdf`, `docx`, `txt` → извлечение текста (с лимитами)
  - неизвестные типы → метаданные без падения

Ошибки парсинга:
- сохраняются в поле `parse_errors`
- не прерывают обработку письма

---

### 4. Препроцессинг
**Файл:** `app/preprocessing.py`

Функции:
- очистка и нормализация текста
- извлечение URL
- ограничение длины текста (clip)
- HTML → plain text

---

### 5. ML-классификатор
**Файл:** `app/classifier.py`

Подход:
- zero-shot классификация
- без обучающей выборки
- категории задаются пользователем

Шаги:
1. эмбеддинг письма (`query`)
2. эмбеддинги категорий (`passage`)
3. cosine similarity
4. сортировка → top-N
5. softmax (для относительных confidence)
6. бизнес-решение:
   - если `max_similarity < threshold` → «Не определена»

Контракты:
- `RawClassificationResult` — ML-результат
- `DecisionResult` — финальное бизнес-решение

---

### 6. Эмбеддинги
**Файл:** `app/embeddings.py`

- SentenceTransformers
- мультиязычная модель (`settings.EMBEDDING_MODEL_NAME`)
- E5-совместимый формат (`query:` / `passage:`)
- L2-нормализация эмбеддингов

---

### 7. Security / Robustness (MVP)
**Файл:** `app/security.py`

Флаги безопасности:
- `prompt_injection_flag`
  - простые regex-паттерны
- `phishing_risk_score`
  - ключевые слова
  - количество ссылок
  - подозрительные домены (IP, punycode)

⚠️ Эвристики, не полноценная ИБ-система.

---

### 8. Хранилище результатов
**Папка:** `results/`

Форматы:
- `results.csv` — основной артефакт
- `results.jsonl` — опционально

Особенности:
- append-only логика
- стабильная схема колонок
- каждая строка = одно письмо = один запрос

---

## Data Flow (Pipeline)

```
UI (Streamlit)
   ↓
FastAPI (/classify/batch)
   ↓
Email parsing (.eml / .msg)
   ↓
Text preprocessing + attachments
   ↓
Security signals (optional)
   ↓
Embeddings (email + categories)
   ↓
Cosine similarity
   ↓
Top-N ranking
   ↓
Threshold decision («Не определена»)
   ↓
CSV / JSONL export + logs
```

---

## Устойчивость и ограничения (MVP)

- лимиты:
  - размер вложений (`MAX_ATTACHMENT_BYTES`)
  - страницы PDF (`MAX_PDF_PAGES`)
- неизвестные форматы вложений:
  - не приводят к падению сервиса
- ошибки парсинга:
  - фиксируются в результатах
  - классификация продолжается по доступному тексту
- `.msg`:
  - best-effort, зависит от окружения
